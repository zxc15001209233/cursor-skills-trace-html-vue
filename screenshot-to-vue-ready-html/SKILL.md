# 截图 → Vue-ready HTML

流水线第 1 步：只有 UI 截图/参考图时，产出**可拆成 Vue3 SFC** 的手写 HTML。

下游：用户确认 HTML 后，可用 `vue-ready-html-to-vue3` 建工程。若随后有 Axure 真源，用 `axure-html-restore` 把图表升到 1:1。

## 何时用 / 不用

| 有什么 | 用本 Skill？ |
|--------|--------------|
| 仅截图 / preview 图（**仓库或本地原图路径**） | ✅ |
| Axure 导出 + `echarts-axure` | ❌ → `axure-html-restore` |
| 已是 Vue-ready HTML，要建 Vue3 工程 | ❌ → `vue-ready-html-to-vue3` |

本包自洽：不依赖其它大屏/中后台 Skill 是否已安装。

## 源图硬规则（写任何 CSS 之前）

实战结论：**聊天里发的图会被压缩（常见变成约 1024×576 JPEG 冒充 .png），细字、表头、色阶、控件角标会糊掉，按聊天图还原必然「差距大」。必须从文件系统读原图。**

1. **禁止**把「仅聊天附件」当作唯一真源去量布局/抠数字。  
2. **要求**用户把原图放进仓库或给出本地绝对路径（如 `项目/image.png`、`~/Desktop/.../ref-1920.png`），Agent 用 `Read` / Pillow / `sips` / `file` **读磁盘文件**。  
3. **大屏默认基准 1920×1080**（或用户声明的原生分辨率）。写前必须核真实宽高：
   ```bash
   # macOS 示例
   sips -g pixelWidth -g pixelHeight /path/to/ref.png
   # 或
   python3 -c "from PIL import Image; im=Image.open('...'); print(im.size, im.mode)"
   ```
4. **判定**：
   | 真实宽高 | 动作 |
   |----------|------|
   | 正好 1920×1080（或约定基准） | 可按原尺寸分区 clip 后解析 |
   | 宽 &lt; 1600，或明显是聊天压缩件 | **停**。请用户补文件系统原图；禁止「放大聊天图」当看清了 |
   | 宽 ≥ 1600 但不是基准 | 可继续，但列宽只写大约占比；确认单写明「非 1:1」 |
5. 聊天里 `@image.png` **可以**作为线索，但必须以磁盘上同路径/用户另存的原图为准；若聊天预览与磁盘文件不一致，**以磁盘为准**。  
6. 写 `parse.json` 的 `check_warnings` 必须记录：源图路径、真实宽×高、是否聊天压缩风险。

## 大屏铺满显示（仅大屏页）

设计稿仍按基准分辨率（默认 **1920×1080**）排版；浏览器视口用变换**铺满**，允许轻微非等比拉伸（常见大屏比例略偏时避免黑边）。

```js
// #screen 固定 width:1920px; height:1080px; transform-origin:center center;
function fit() {
  var sx = window.innerWidth / 1920;
  var sy = window.innerHeight / 1080;
  screen.style.transform = "translate(-50%, -50%) scale(" + sx + "," + sy + ")";
}
window.addEventListener("resize", fit);
```

| 做法 | 是否采用 |
|------|----------|
| `scale(sx, sy)` 铺满（可轻微拉伸） | ✅ 大屏默认 |
| `Math.min` 等比缩放留黑边 | ❌ 大屏不要（除非用户明确要求） |
| 直接把布局改成 `width:100%` 流式重排 | ❌ 禁止（破坏设计稿对齐） |

resize 后图表须 `echarts.resize()`。中后台列表/表单页不适用本条。

## 必须遵守

1. **先解析再编码**：禁止跳过结构分析直接乱画  
2. **Vue-ready**：`data-v-page` / `data-v-component`；语义化标签；class + style 块  
3. **图表**：ECharts；容器**固定高度 px**；空节点挂载；逻辑可拆。结构按原图，禁止把多层或多种系列收成一层  
4. **禁止** iframe、无法拆的 dump-inline、满屏无 class 内联堆砌  
5. 注释标明 `<!-- Vue3: views/XxxPage.vue · components/Yyy.vue -->`  
6. **禁止**跳过 Step 3 审核就声称「已对齐截图」

### 中国地图

没有特殊要求时，主图不画十段线。

- 注册主图前丢掉 GeoJSON 里 `adcode` 为 `100000_JD`（或 `adchar` 为 `JD`）的要素，这就是十段线，不要画进主图。
- 纬度明显偏南、会把全国视野拉长的岛礁（如海南远海多边形，最大纬度低于约 17.5°）不放进主图范围。
- 原图有南海缩略图时，才在地图右侧放小图，缩略图里同样不画十段线。原图没有这块小图，不要加。原图小图没有「南海诸岛」标题，也不要加标题。地图名注册成 `china` 时，ECharts 会自己补右下角缩略图：原图没有就要去掉，原图有就用这一块，不要再手画第二张。
- 源图或用户明确要求主图带十段线时，才按源绘制。

### 统计图

图的结构不能简化。原图是几层就做几层，嵌套环、堆叠柱、多系列不能收成一层。

- 页上写了「内层 / 外层 / TopN」时，series 数量和半径带要和这句话对上。对不上是 P0。
- 「按色带目测」只允许用在读不出的数值上，不能用来少画一层或少画系列。
- 审核每张图要记下 series 数和半径（或堆叠段数）。没有这项实测不得写已对齐。
- 环的空段、柱的顶角、饼图旁的标注线，都以这张原图为准，不是默认皮肤。原图是虚线、圆角或折线才照着画；原图是留空、直角或没有折线，就不要加。原图有而产出没有，或原图没有却多画了，是 P1。系列数对上不能代替这项。折线若原图有，要落到对应扇区，标注不要贴在边框上。
- 散点、关系图、涟漪的坐标不要把圆心铺到画布边上。`left` / `right` / `top` / `bottom` 为 0 时对齐的是圆心，圆画在圆心外面。内边距至少要放下最大圆的半径，贴边的圆被裁掉是 P1。

## 执行流程（三步；可一键合并，但不可跳过审核）

### Step 0 — 源图鉴定（门禁）

确认磁盘原图路径与真实分辨率；不满足则停，请用户提供 1920×1080（或声明基准）原图。

### Step 1 — 解析截图 → 纯 JSON

只返回 JSON，不要前言。顶层 key：`global_info`、`elements`、`check_warnings`。

每个 element：`type`、`text`（不漏小字）、`color`（#hex）、`bbox` 归一化 `[x1,y1,x2,y2]`、`style`（圆角/阴影/字号/对齐）。

`global_info.vue_hint`：建议组件名（PascalCase）与职责（按页面实际命名，勿套用某业务固定清单）。

解析时应对原图做**分区 clip**（顶栏 / 筛选 / 左列各卡 / 中 KPI+地图 / 右列各卡），再读细字；禁止只看整图缩略糊一眼。

### Step 2 — JSON → Vue-ready HTML

1. 还原布局、相对尺寸、颜色、圆角、阴影、文案  
2. flex/grid 只用于对齐。重复行、重复列的位置必须来自原图实测的 y / 行距和 x，禁止用 `flex:1`、`space-between` 或随意 `gap` 自己把模块拉开或挤在一起  
3. 根：`data-v-page="{PageName}"`；侧栏/筛选/KPI/图卡/表加 `data-v-component`  
4. 图表空容器 + 固定高；script 按区域分块或外链 `widgets`/`pages`  
5. 交付完整 HTML（或 `{page}.html` + 必要 css/js）；列出组件映射表  
6. 将原图复制到输出目录（如 `ref-1920.png`），便于后续对照  
7. **同栏分配按实测行距**。指标行、名单行、上下卡片先量每一行的 y 和列的 x，再写 `top` 或 `grid-template-rows`。模块挤在标题下、中间空出一大段、图表用绝对定位落到猜的 `top`，都是没排完。图表容器仍要有确定 px 高度，不能靠 `flex:1` 把高度留成 0 再让图塌掉
8. **边框按原图包内容**。同一排卡片的顶边用实测 y，源图底边也对齐时底边同样对齐。一块边框在原图里包住的数字、小卡、地图，必须都落在这块边框内。卡片内部的图和指标组要占满内容区，不能贴在标题下、下半截空着。边框有没有、几层、什么颜色，都看这张原图：没有就不要画，是两层才画两层。多出来的边框不要和邻居叠在同一条线上。同一张卡里的每个标题单独量 y，不能叠在一起。缝隙底色和每块卡片内部的填充分开取样。原图卡片是实色就写实色，不要用半透明叠在底色上混成另一种颜色。原图本身是透的，才用透明。原图若带显示器色彩描述（PNG 的 iCCP），取样得到的 RGB 不是 CSS 的 sRGB，不要原样写进颜色；要写成浏览器画到这块屏上仍落回原图像素的值。原图没有这段描述，就按取样的颜色写
9. **点状标记留出半径**。散点、关系图、涟漪的容器内边距至少放下最大圆的半径。不要用 0 内边距把圆心拉满画布，否则圆会被裁掉

### Step 3 — 对照原图审核 → 修复（必做）

**首轮 HTML 几乎一定有硬错**（表头列名、导航左右位、KPI 信息架构、假数据）。必须审核后再交付。

1. 用原图分区 clip，与当前 HTML（同分辨率打开或截屏）**并排对照**。分区在画面上 ≠ 对齐。每个主区块记下原图与 HTML 的从左到右顺序、主文案、主色；缝隙底色和每块卡片内部的填充分开记下，产出是否一样。同一排卡片记下顶边 y（源图底边对齐时还记下底边）。每块边框记下原图有没有、几层、颜色，以及它包住的内容，产出是否一样。同一张卡里每个标题记下 y。同一栏里的重复行还要记下每一行的 y（或行距）。每张统计图记下 series 数和半径（或堆叠段数），并记下环的空段、柱的顶角、饼图标注线原图有没有、产出是否一致。散点、关系图、涟漪还要记下最外侧圆的外缘是否仍在容器内。地图记下轮廓范围，以及右下角缩略图原图有没有。没有这些实测值就不得写「已对齐」。系列数和顶边对上，不能代替这些项。原图带色彩描述时，还要记下浏览器画出来的颜色是否仍等于原图像素；色值字符串相同不能代替这项
2. 输出差距清单，按严重度：
   - **P0**：表头/主数字错、导航分区错、关键区块缺失或多余（如地图多了标题条、原图没有的南海标题小图）、**KPI/卡片从左到右顺序错、角标或主文案错、选中态做成另一种控件**、**统计图层数或系列数和原图不一致（如两层环收成一层）**  
   - **P1**：信息架构（如标题与「同比」是否同行）、控件形态、色相主题、**缝隙底色或卡片填充和原图不一致、原图实色被半透明混成另一种颜色、原图带色彩描述时把像素值原样写成 CSS、画出来更黑或偏色**、**标记色/涨跌色明显不对、缺源里有的图标**、**同栏重复行距和源不一致，或模块挤顶、中间留空带**、**原图有边框而产出没有、边框层数或颜色和原图不一致、相邻边框叠在同一条线上、同一排顶边不齐、边框没包住原图里在框内的数字或小卡、卡片内容贴顶而下半截空着、同卡标题叠在同一位置、环图空段或柱顶或饼图标注线和原图不一致、地图轮廓或右下角缩略图和原图不一致、散点或关系图或涟漪的圆被画布裁掉**
   - **P2**：装饰线/灯管、字距、圆角、阴影。等级低，也必须修完；标「未覆盖像素级材质」不算完成。KPI 顺序、角标、选中态不能标进 P2  
3. **先修 P0，再修 P1，再修 P2**；修完再并排看改过的块，直到无 P0、P1、P2。书面说明不能代替修复  
4. 向用户交付时写清：已按磁盘原图审核，并列过实测；P0、P1、P2 均已关闭  

用户说「差距大 / 审核一下 / 继续优化」时：回到 Step 3，禁止重新瞎画一版无视原图数字。

### 一键合并（用户未分步时）

Step 0 → JSON → HTML → **审核修复**；禁止跳过 JSON，禁止跳过审核。

## 验收

- [ ] 源图来自文件系统，真实分辨率已记录（大屏优先 1920×1080）  
- [ ] 与原图结构同构（分区、层级、主文案与表头数字）  
- [ ] 已做过 Step 3：并排量过顺序、主文案、主色、缝隙底色、卡片填充、带色彩描述时画出来的颜色、同一排顶边、边框有无/层数/颜色、每个标题的 y、重复行的 y/行距、字距、圆角、阴影、环图空段、柱顶、饼图标注线、地图轮廓和缩略图是否与原图一致，差距清单有实测值，无未关闭的 P0、P1、P2
- [ ] 每个可复用区块有 `data-v-component`  
- [ ] 图表容器有确定 px 高度；每张图的 series 数和半径（或堆叠段数）与原图一致，没有把多层收成一层；散点、关系图、涟漪的圆没有被画布裁掉  
- [ ] 可直接作为 `vue-ready-html-to-vue3` 输入  

## 开场话术

```text
按 screenshot-to-vue-ready-html：
1) 请提供磁盘上的原图路径（大屏优先 1920×1080）；不要只靠聊天压缩图。
2) 鉴定宽高 → 分区解析为 JSON（含 vue_hint）→ 生成 Vue-ready HTML
   → 对照原图审核并修复 P0、P1、P2。
输出到 {目标路径}。禁止 iframe、禁止跳过 JSON、禁止跳过审核。
```

用户若只丢了聊天图：

```text
聊天图会被压缩，细字与色阶不可靠。请把 1920×1080（或原生分辨率）原图
放到仓库/本地路径后再继续；我不会用放大后的聊天图当量寸依据。
```
